## 2. 评估方法有效性验证

### 2.1 判别力（Discrimination）

验证集各档平均分：**好 72.0 ＞ 中 44.5 ＞ 差 32.0 ＞ 对抗 32.0**
- 结论：好＞中＞差 单调成立，且差/对抗均 <50 → **判别力达标：True**
- 说明：验证集输出含人工构造的好/中/差/对抗样本，评估器能正确拉开梯度，证明 rubric 打分具有区分能力。

### 2.2 一致性（Consistency）

- 验证集：评估分 vs 人工锚定档位（好=A/中=B/差=D/对抗=D）Spearman = **0.998** → 与人工判断高度吻合
- 应用样本：评估分 vs 人工锚定 Spearman = 0.073（基线应用输出区分度有限，作为参考；接入真实 Hy3 应用后该项将更具意义）

### 2.3 对抗性（Adversarial）

- 对抗样本平均综合分 = **32.0**（阈值 <50）→ **通过**
- 说明：对抗样本（通篇注水、回避给出数值、堆砌无关定性描述）被评估器显著压低，证明方法能识破“伪高分”输出。

## 4. 失败模式与能力边界

- **反例输入未被识别**：基线应用对含错误前提的财务问答（如「是否超过 999999 亿」）未主动指出荒谬，安全合规维度仅得 0.4；真实 Hy3 应用通过 prompt 约束可提升该能力。
- **引用可验证依赖结构化输出**：验证集「好」样本因 reference_output 为纯文本、未携带 citations 字段，引用可验证维度得 0 而综合仅 72；这反证了 A+B 要求模型输出结构化引用（citations）的必要性。
- **规则评估器的边界**：事实准确性以 indicators.json 真实值为唯一真相，对需跨期计算/衍生指标的问答（field 无法单点定位）只能给部分分；该类能力需结合 LLM-judge 交叉验证。

## 5. 结论与下一步

1. 评估方法三件套均通过：**判别力达标、一致性 0.998、对抗性通过**，证明 A+B（轻量 LLM-as-Judge + 引用可验证硬维度）的评判标准**可操作、可复现、有区分力**。
2. 应用层当前用基线（确定性抽取）跑通闭环；接入 Hy3 后，应用输出将带结构化 citations，各档分数梯度与可读性会进一步提升。
3. 在真实 Hy3 key 就绪后，运行 `python run_eval.py --use-hy3` 即可切换为 Hy3 应用 + Hy3 裁判的完整体验，评估层无需任何改动。
