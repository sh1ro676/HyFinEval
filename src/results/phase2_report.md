# Phase 2：per-subtask 维度重加权 / 拟合打分器（LOO-CV）

> 目标：在方案A 之后的评估器基线上，用 28 条人工标注池拟合 7 维
> （factual / citation / completeness / format / safety / computation / calibration）
> 的线性打分器，以留一交叉验证测排序相关性的诚实上界，看能否把 ρ 再往上拉。

## 基线

- 人工标注为**三档**（优 / 中 / 差），映射为序数 3 / 2 / 1。
- `src/label_stats.py` 已报告：`auto_vs_humanA_spearman = 0.275`、κ = 0.663、
  分档相邻一致率 0.893；本脚本独立复算得到 **0.275**，与之一致，交叉验证通过。

## 方法

1. 用当前（方案A 后）`evaluator.evaluate()` 重算 28 条样本的 7 维分数
   （缓存于 `data_cache/auto_dims_pool.json`，可复现）。
2. 目标 `y` = 人工标注档位序数（优 3 / 中 2 / 差 1）。
3. 拟合：以 `rank(y)` 为因变量对 7 维做最小二乘回归得权重 `w`，取 `Spearman(w·X, y)`。
4. **诚实估计用 LOO-CV**：每次留 1 条，在余下 27 条上拟合后对该条预测，
   汇总 28 条 LOO 预测再算 Spearman——用于暴露过拟合。

## 结果（n = 28）

| 方法 | in-sample ρ | LOO-CV ρ | 评价 |
|---|---|---|---|
| **基线**（当前评估器加权分） | — | **0.275** | 最强且最稳 |
| 朴素 7 维线性拟合 | 0.390 | **−0.139** | 严重过拟合，远低于基线 |
| per-subtask 偏置校正（每子任务 1 参数） | 0.170 | 0.067 | 低于基线 |
| 岭回归全局（λ=100） | — | 0.109 | 低于基线 |
| per-subtask 全维拟合组合（诊断） | 0.300 | — | 不稳定 |

per-subtask 组内 in-sample Spearman（诊断）：
财报指标提取 0.273（n=9） / 财务问答 **0.0**（n=11，组内无信号） / 公告摘要 0.677（n=8）。

## 结论

**在 n=28 下，任何数据驱动的重加权都未能在 LOO-CV 上超过当前手工权重评估器，且普遍更差。**
朴素 7 维拟合 in-sample 有 0.390，但 LOO 掉到 −0.139——典型的过拟合；
加约束的偏置校正（0.067）与岭回归（0.109）同样低于基线 0.275。
即：样本量不足以稳定地学出维度权重，**当前手工权重评估器已是最稳选择**。

子任务层面分化明显：财务问答组内 ρ=0.0（11 条里几乎无可学习信号），
公告摘要组内 0.677（8 条，维度组合有判别力但样本太少）。

**真正能把 ρ 再往上拉的杠杆不是「调权重」，而是：**

- **E. 扩样本**：把人工标注池从 28 条扩到 ≥60–80 条，拟合才有稳定解。
- **C. pairwise 人类真值**：改「绝对分档」为「谁好谁差」的成对偏好标注，更便宜、噪声更低，
  且天然规避分数膨胀与档位压缩问题。
- **公告摘要**已有开卷/闭卷配对数据与客观真值（`data_cache/ann_*.json`），
  可用于重建该子任务的判别力，组内 0.677 提示它值得优先扩样本。
