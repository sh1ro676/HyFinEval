# Phase 2：per-subtask 维度重加权 / 拟合打分器（LOO-CV）

> 目标：在已提交基线（评估器 `auto_score` vs 人工标注 A）之上，用 28 条人工标注池
> 拟合 7 维（factual / citation / completeness / format / safety / computation / calibration）
> 的线性打分器，测排序相关性（Spearman）的诚实上界，看能否把 ρ 再往上拉。

## 基线（dfd41a1，当前已提交状态）

- `src/label_stats.py` 提交值：`auto_vs_humanA_spearman = 0.635`（简化秩、不平均并列）。
- 本脚本用标准 Spearman（平均并列秩）复算：`ρ = 0.622`。两者口径一致，约 **0.62–0.64**。

> 说明：此前工作笔记里记过 `ρ=0.050`，那是某次**从未提交的过渡态**测得值；
> 真正提交到仓库的基线一直是 ~0.62。因此"方案A 把 ρ 从 0.05 拉到 0.275"这批改动
> 虽随本地仓库丢失，但**不影响当前可用基线**——当前基线本就强于笔记记忆。

## 方法

1. 用 `evaluator.evaluate()` 重算 28 条样本的 7 维分数（`data_cache/auto_dims_pool.json`，可复现）。
2. 目标 `y` = 人工标注者 A 的数值分（0–100）。
3. 拟合：以 `rank(y)` 为因变量对 7 维做最小二乘回归得权重 `w`，`Spearman(w·X, y)`。
4. **诚实估计用 LOO-CV**：每次留 1 条，于余下 27 条拟合，对该条预测，汇总 28 条 LOO
   预测后算 Spearman——这是泛化上界，可暴露过拟合。

## 结果（n = 28）

| 方法 | in-sample ρ | LOO-CV ρ | 评价 |
|---|---|---|---|
| **基线**（当前评估器加权分） | — | **0.622** | 最强且最稳 |
| 朴素 7 维线性拟合 | 0.711 | **0.493** | 过拟合，远低于基线 |
| per-subtask 偏置校正（每子任务 1 参数） | 0.641 | 0.576 | 略低于基线 |
| 岭回归全局（λ=1.0） | — | 0.590 | 略低于基线 |
| per-subtask 全维拟合组合（诊断） | 0.352 | — | 不稳定，公告摘要 n=5 退化 |

per-subtask 组内 in-sample Spearman（诊断）：财报指标提取 0.748 / 财务问答 0.860 / 公告摘要 None（n=5 退化）。

## 结论

**在 n=28 下，任何数据驱动的重加权都未能在 LOO-CV 上超过当前手工权重评估器。**
朴素 7 维拟合看着 in-sample 0.71，但 LOO 掉到 0.49（过拟合）；加约束的偏置校正 / 岭回归
也只有 0.58 左右，仍低于基线 0.62。即：样本量不足以稳定地学出维度权重。

**真正能把 ρ 再往上拉的杠杆不是"调权重"，而是：**

- **E. 扩样本**：把人工标注池从 28 条扩到 ≥60–80 条，拟合才有稳定解（这也是
  `human_alignment.json` 中 95% CI 长期覆盖 0 与 0.4 的根因）。
- **C. pairwise 人类真值**：改"绝对分档"为"谁好谁差"的成对偏好标注，更便宜、噪声更低，
  且天然规避分数膨胀问题。
- 公告摘要因闭卷无原文、n=5 退化，需补"开卷（喂真实公告原文）"配对样本才有判别力
  （此前的公告重建工作已证明开卷覆盖率 0.511 vs 闭卷 0.016，但该批脚本随本地仓库丢失，需重建）。
